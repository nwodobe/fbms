# Critères de recette — Sacherie Control Tower

La release ne doit être considérée comme prête que si :

1. le total du patrimoine est explicable par les mouvements ;
2. un transfert interne ne change jamais le total global ;
3. un changement d'état ne change jamais le total global ;
4. une perte ne réduit le total qu'après approbation BM ;
5. le stock cluster, RT, producteur et hub est visible séparément ;
6. les sacs déchirés, à réparer, réparés et REBUT sont visibles ;
7. le stock physique n'est jamais inventé en l'absence d'inventaire ;
8. tout écart d'inventaire est HOLD et requiert une justification ;
9. les utilisateurs terrain sont limités à leur cluster ;
10. une dotation RT directe sans approval SOP-006 est impossible côté serveur ;
11. les chiffres du dashboard peuvent être reliés au journal de mouvements ;
12. les trois tailles d'écran de recette sont utilisables sans blocage.
