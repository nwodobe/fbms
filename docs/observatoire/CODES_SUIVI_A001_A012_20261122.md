# Observatoire AFLP 2027 — codes de suivi A001 à A012

Mandat du Branch Manager du 22/11/2026. Branche `feat/observatoire-codes-suivi-a001-a012`, construite sur la PR #369.

## Règle

| Donnée | Exemple | Qui la fixe | Change ? |
|---|---|---|---|
| Identifiant technique de l'arbre (`pheno_arbres.id`) | uuid | calculé (bloc + numéro) | jamais |
| Bloc physique | B02 | installation du champ | jamais |
| Numéro d'inventaire dans le bloc / code physique (`pheno_arbres.code`) | 1 / `B02/A001` | inventaire | jamais |
| **Code de suivi** (`pheno_arbres.code_suivi`) | **A004** | Chef d'Unité, librement | seulement par modification motivée et journalisée |
| Rôle | suivi 04, réserve R1 | Chef d'Unité | remplacement motivé (inchangé) |

- Codes autorisés : A001 à A012, chacun **exactement une fois par champ** (unicité par panel ; un autre champ peut réutiliser A001).
- Les deux réserves ont leur propre code ; une réserve activée garde son code.
- Le code de suivi ne remplace jamais le code physique d'inventaire (B01/A001 reste écrit partout où il l'était).

## Interface (Fiche du champ → « Désigner les 10 arbres suivis et les 2 réserves »)

Chaque ligne : rôle (Arbre suivi 01…10, Réserve R1, R2), bloc, arbre physique (n° dans le bloc), code de suivi.
- « Proposer les 12 arbres physiques sans doublon » : remplit bloc + numéro à partir des inventaires réels (PR #369).
- « Attribuer automatiquement A001 à A012 » : remplit les codes dans l'ordre des lignes ; chaque code reste modifiable.
- Code déjà utilisé : erreur immédiate sur la ligne et bouton « Échanger » (l'autre ligne reçoit l'ancien code).
- Compteur : « 12/12 arbres identifiés, 0 doublon. » ; « Enregistrer » actif seulement si 12 codes uniques, 12 arbres physiques distincts et numéros dans l'inventaire.
- Brouillon gardé dans IndexedDB (`anagroci_observatoire` / `meta` / `choix:<panel>`) à chaque saisie, restauré à la réouverture, effacé après enregistrement.
- Fiche du champ : colonne « Code de suivi », bouton « Modifier les codes de suivi… » (Chef d'Unité ou Branch Manager, réseau nécessaire, motif obligatoire, échange proposé). Champ installé avant la migration : bouton « Attribuer les codes A001 à A012 ».
- Visite hebdomadaire : arbres présentés par code de suivi, en-tête « Code de suivi A004 · arbre physique B02/A001 ».
- Si le serveur n'a pas encore la migration 7, le formulaire reste celui de la PR #369 (pas de colonne code) et l'indique.

## Serveur — migration 7

`supabase/20261122140000_aflp_observatoire_7_codes_suivi.sql` (additive, rejouable) :
- colonnes `pheno_arbres.code_suivi`, `code_suivi_le`, `code_suivi_par` ; contrainte de format `^A0(0[1-9]|1[0-2])$` ;
  contrainte `unique (panel_id, code_suivi) deferrable` (échanges en une instruction) ;
- `pheno_observations.code_suivi` + déclencheur : chaque observation garde le code en vigueur à sa création ;
- `pheno_arbres_designer` : accepte `code_suivi` (tous ou aucun ; aucun = ancien téléphone → ordre par défaut A001..A010, R1 = A011, R2 = A012),
  refuse doublon, code hors liste, liste partielle ; rejeu identique accepté ; désignation différente sur un champ déjà désigné = **CONFLIT PH409** (deux appareils) ;
- `pheno_arbres_codes_modifier(p jsonb)` : attribution ou modification des 12 codes, Chef d'Unité du cluster ou Branch Manager, motif obligatoire, `base_version` contrôlée (conflit si le champ a changé), journal immuable `CODES_SUIVI_ATTRIBUES` / `CODES_SUIVI_MODIFIES` avec anciens et nouveaux codes.

Retour arrière : `supabase/20261122140100_aflp_observatoire_7_rollback.sql` — retire la nouvelle RPC et le déclencheur, remet `pheno_arbres_designer` à l'identique de la migration 5, **conserve** colonnes et valeurs (bloc destructif commenté, sur décision explicite uniquement).

**Ordre de mise en production : migration 7 d'abord, puis la mise à jour Web (OTA).** Avec l'ordre inverse, le formulaire reste en mode PR #369 (garde `codes_suivi` du protocole), sans perte.

## Conséquences vérifiées

- Photos : nom de fichier et contrôle serveur fondés sur l'identifiant technique de l'arbre → inchangés.
- GPS des arbres : rattaché à l'identifiant → inchangé ; info-bulle de la carte des parcelles : « A004 (B02/A001) ».
- Historique : visites antérieures affichées avec `pheno_observations.code_suivi` (code d'origine).
- Exports / vues pilote : aucune vue ne publie le code d'arbre ; non modifiées.
- Inventaires : jamais modifiés ; aucun arbre créé ni supprimé.

## Limites connues

- Une visite saisie hors ligne **avant** une modification de code, puis synchronisée **après**, prend au serveur le code en vigueur à la réception (le déclencheur copie le code de l'arbre). L'arbre (identifiant et code physique) reste exact.
- La modification des codes exige du réseau (comme le remplacement d'un arbre).
